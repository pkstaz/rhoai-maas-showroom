= ODHDashboardConfig

Enciende Model Catalog, MaaS en la UI, Gen AI Studio, EvalHub (menú Evaluations) y Kueue. *No* actives `vLLMDeploymentOnMaaS`: este lab despliega con *llm-d*.

NOTE: El menú *Gen AI Studio → Playground* también exige `ogx: Managed` en el `DataScienceCluster` (ver xref:03-02-dsc.adoc[DataScienceCluster]). La página *Evaluations* exige TrustyAI + EvalHub desplegado (xref:12-00-evalhub.adoc[módulo 12]) y, para la UI completa, MLflow.

== UI

La pestaña *OdhDashboardConfig* no aparece en el Operator de OpenShift AI. Ábrelo así:

. Consola OpenShift → *Home* → *Search*
. En *Resources*, busca `OdhDashboardConfig` (con `OdhDash` alcanza)
. Abre `odh-dashboard-config` en el namespace `redhat-ods-applications`
. Pestaña *YAML*
. En `spec.dashboardConfig` deja (o añade) esto:

[source,yaml]
----
disableModelCatalog: false
disableModelRegistry: false
disableKueue: false
modelAsService: true
genAiStudio: true
disableLMEval: false
----

. *Save*

O, más rápido, desde el Web Terminal:

[source,bash]
----
oc patch odhdashboardconfig odh-dashboard-config -n redhat-ods-applications --type merge -p '{
  "spec": {
    "dashboardConfig": {
      "disableModelCatalog": false,
      "disableModelRegistry": false,
      "disableKueue": false,
      "modelAsService": true,
      "genAiStudio": true,
      "disableLMEval": false
    }
  }
}'
----

Hard refresh del dashboard de OpenShift AI (`Cmd+Shift+R` / `Ctrl+Shift+R`).

== Verificar

[source,bash]
----
oc get odhdashboardconfig odh-dashboard-config -n redhat-ods-applications \
  -o jsonpath='{.spec.dashboardConfig}' | jq
----

En el dashboard deben verse *Catalog* / *Models as a Service* (el nombre exacto depende de la build).
