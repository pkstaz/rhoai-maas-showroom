= GatewayClass y Kuadrant

El Operator de Connectivity Link ya está en `openshift-operators` (módulo 2). Eso coincide con la doc de OpenShift AI 3.5.

La instancia *Kuadrant* no va ahí: va en **`kuadrant-system`**. Authorino y Limitador se despliegan en ese namespace.

== 1. GatewayClass

[source,bash]
----
oc apply -f examples/gatewayclass.yaml
oc get gatewayclass openshift-default
----

`GatewayClass` es de *cluster* (sin namespace). `ACCEPTED` = `True` basta.

== 2. Controller name (OpenShift)

Kuadrant busca Istio/Envoy por defecto. En este lab el controller es `openshift.io/gateway-controller/v1`. Sin este env, el CR queda en `MissingDependency`:

[source,bash]
----
oc patch subscription rhcl-operator -n openshift-operators --type merge -p '{
  "spec": {
    "config": {
      "env": [{
        "name": "ISTIO_GATEWAY_CONTROLLER_NAMES",
        "value": "openshift.io/gateway-controller/v1"
      }]
    }
  }
}'

oc get deploy -n openshift-operators -o name | grep -i kuadrant
oc rollout restart -n openshift-operators \
  $(oc get deploy -n openshift-operators -o name | grep -i kuadrant)
----

Espera a que el pod del operator vuelva a `Running`.

== 3. Instancia Kuadrant en kuadrant-system

Si creaste el CR en `openshift-operators`, bórralo y recréalo aquí:

[source,bash]
----
oc create namespace kuadrant-system --dry-run=client -o yaml | oc apply -f -
oc delete kuadrant --all -n openshift-operators --ignore-not-found
oc apply -f examples/kuadrant.yaml
oc wait kuadrant/kuadrant -n kuadrant-system --for=condition=Ready --timeout=5m
----

Desde la UI:

. Cambia el proyecto a `kuadrant-system` (créalo si no existe)
. *Installed Operators* → *Red Hat Connectivity Link* (project: `kuadrant-system`)
. Crea *Kuadrant*. Nombre: `kuadrant` (no `kuadrant-sample`)

== Verificar

[source,bash]
----
oc get kuadrant -n kuadrant-system
oc get pods -n kuadrant-system
----

`Ready` y pods de Authorino / Limitador `Running`.
