= Operadores previos

Antes de OpenShift AI hace falta un conjunto *fijo* de operadores de plataforma.
Sin ellos no podrás exponer MaaS por Gateway con TLS, usar AI Pipelines, repartir inferencia con llm-d ni reservar GPU con Kueue.

Canal y namespace: los que propone el *Software Catalog*, salvo que la tabla indique otra cosa.

== Validar instalados y pendientes

Ejecuta esto *antes* de instalar (y otra vez al final). `OK` = CSV `Succeeded`; `PENDIENTE` = aún no está o no terminó:

[source,bash]
----
printf '%-42s %-14s\n' "OPERADOR" "ESTADO"
printf '%-42s %-14s\n' "------------------------------------------" "--------------"
check() {
  local name="$1" pattern="$2"
  local line phase
  line=$(oc get csv -A --no-headers 2>/dev/null | grep -iE "$pattern" | head -1)
  if [ -z "$line" ]; then
    printf '%-42s %-14s\n' "$name" "PENDIENTE"
  else
    phase=$(echo "$line" | awk '{print $NF}')
    if [ "$phase" = "Succeeded" ]; then
      printf '%-42s %-14s\n' "$name" "OK"
    else
      printf '%-42s %-14s\n' "$name" "$phase"
    fi
  fi
}
check "cert-manager" "cert-manager"
check "OpenShift Pipelines" "pipelines"
check "Connectivity Link" "connectivity"
check "Leader Worker Set" "leaderworker|lws"
check "Kueue" "kueue"
----

== Operadores requeridos

[cols="1,2"]
|===
|Operador |Para qué sirve

|*cert-manager Operator for Red Hat OpenShift*
|Emite y renueva certificados TLS. Los usa el stack de *Gateway API* / *AI Gateway* para HTTPS en las rutas que exponen *Models as a Service* (y endpoints relacionados del lab).

|*Red Hat OpenShift Pipelines*
|Base Tekton para habilitar *AI Pipelines* en OpenShift AI (pipelines de datos / ML desde la consola más adelante).

|*Red Hat Connectivity Link*
|Capa de *Gateway API* + políticas (Kuadrant): enrutado, auth y límites delante del *AI Gateway* / MaaS. Instala *solo el Operator* ahora (`openshift-operators`, All namespaces). El `GatewayClass` y la instancia Kuadrant van en el módulo 4, *después* de OpenShift AI.

|*Leader Worker Set Operator*
|Coordina pods *líder + workers* para inferencia distribuida. llm-d lo usa cuando un modelo no cabe en un solo pod y hay que repartirlo. Namespace `openshift-lws-operator`, canal `stable-v1.0`.

|*Red Hat build of Kueue*
|*GPU Booking*: colas y cuotas para que los jobs de GPU no saturen el cluster.
|===

== Orden de instalación

En la consola: *Ecosystem* → *Software Catalog*. Instala uno, espera *Succeeded*, sigue al siguiente (mismo orden que la tabla).

== Manifiestos por operador

Si prefieres CLI (o para repetir en otro cluster), aplica *uno por uno* desde la raíz del repo. Espera `Succeeded` entre cada apply (reutiliza el comando de validación).

=== cert-manager

[source,bash]
----
oc apply -f manifests/operators/cert-manager/
----

=== OpenShift Pipelines

[source,bash]
----
oc apply -f manifests/operators/pipelines/
----

=== Connectivity Link

[source,bash]
----
oc apply -f manifests/operators/connectivity-link/
----

=== Leader Worker Set

[source,bash]
----
oc apply -f manifests/operators/leader-worker-set/
----

=== Kueue

[source,bash]
----
oc apply -f manifests/operators/kueue/
----

== Verificar

Vuelve a ejecutar el comando de *Validar instalados y pendientes*. Todos deben quedar en `OK`.
