= Operadores previos

Instala estas dependencias *antes* de OpenShift AI. Canal/namespace: los que recomienda OperatorHub.

*No* instales OpenShift Serverless ni Service Mesh 2. En 3.x, MaaS y llm-d usan Gateway API. Service Mesh 2 rompe llm-d.

== Orden (UI → OperatorHub)

Instala uno, espera *Succeeded*, sigue al siguiente:

. *cert-manager Operator for Red Hat OpenShift*
. *Red Hat OpenShift Pipelines* (el DSC usará `aipipelines`)
. *Red Hat Connectivity Link* (Kuadrant / Authorino)
. *Red Hat Leader Worker Set Operator* (llm-d)
. *Red Hat build of Kueue* (GPU Booking)

== Connectivity Link

Tras el CSV *Succeeded*:

. *Ecosystem* → *Installed Operators* → *Red Hat Connectivity Link*
. Crea una instancia *Kuadrant* en el namespace del operator (suele ser `kuadrant-system` u `openshift-operators`) con valores por defecto. Nombre: `kuadrant` (la UI propone `kuadrant-sample`; cámbialo).

Si usas el YAML, el `namespace` tiene que coincidir con el del Operator.

O:

[source,bash]
----
oc apply -f examples/kuadrant.yaml
----

[source,bash]
----
oc get kuadrant -A
oc get pods -A | grep -i -E 'authorino|kuadrant'
----

Pods de Authorino / Kuadrant en `Running`.

== Verificar

[source,bash]
----
oc get csv -A | grep -i -E 'cert-manager|pipelines|connectivity|leaderworker|kueue'
----

Todos `Succeeded`.
