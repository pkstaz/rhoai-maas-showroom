= Introducción

Este workshop instala *OpenShift AI {rhoai-version}* en un cluster vacío y deja un modelo *{qwen-model}* publicado en *Models as a Service* (MaaS), servido con *llm-d* en CPU.

El fake GPU no ejecuta CUDA. Sirve para que el cluster anuncie `nvidia.com/gpu` (perfiles, GPU Booking). La inferencia de Qwen corre en CPU.

== Tiempo

* Modo rápido (seguir los clics): *~2 horas*
* Modo explicativo (preguntas, waits, troubleshooting): *~4 horas*
* Contexto Lab → Prd (xref:00-01-lab-a-prd.adoc[módulo 0.1]) + observabilidad (xref:11-00-observabilidad.adoc[módulo 11]) + EvalHub (xref:12-00-evalhub.adoc[módulo 12]): *+60–90 min* extra de lectura y discusión

Los waits largos son el Operator de OpenShift AI y la carga del modelo.

== Qué vas a dejar funcionando

. Web Terminal en la consola
. User-workload monitoring
. OpenShift AI {rhoai-version} + dashboard
. MaaS (gateway, API keys, cuotas)
. GPU opcional: NVIDIA GPU Operator y/o Fake GPU (menús independientes en el módulo 5)
. GPU Config Plugin (solo Fake) y/o MIG nativo (NVIDIA real)
. GPU Booking Console Plugin
. {qwen-model} en el Model Catalog
. Inferencia CPU con llm-d, publicada en MaaS
. Vista inicial de observabilidad MaaS (COO / Perses / usage dashboards — xref:11-00-observabilidad.adoc[módulo 11])
. Smoke de evaluación con EvalHub (xref:12-00-evalhub.adoc[módulo 12])

Los YAML de `manifests/` se clonan en el Web Terminal **después** de entrar como `admin` (módulo 1).

== Qué necesitas

* Cluster OpenShift *4.20+* (llm-d requiere 4.20)
* Entras como `kubeadmin` (así arranca el cluster)
* Después del Web Terminal, usuario `admin` con `cluster-admin`: OpenShift AI no acepta `kubeadmin` en el dashboard
* Storage class por defecto
* Helm 3 y `oc` (el Web Terminal cubre `oc`)
* Salida a `registry.redhat.io`, `ghcr.io`, `huggingface.co`, `quay.io`

== Regla del lab

En cada módulo: *UI primero*. El YAML está al final, colapsado.

No instales OpenShift Serverless / Service Mesh *2*. Este lab usa Gateway API; el Ingress Operator instala solo Service Mesh *3* al crear el `GatewayClass`. GPU (módulo 5): single-node con GPU → solo NVIDIA; single-node CPU → solo Fake; nodos GPU+CPU separados → puedes ambos (Fake nunca en el nodo con GPU real).
