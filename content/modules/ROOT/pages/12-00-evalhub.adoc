= EvalHub (evaluación del modelo)

Prueba de calidad *después* de xref:11-00-observabilidad.adoc[observabilidad MaaS], para no ensuciar los dashboards de Usage con el tráfico del benchmark.

Nada más obligatorio entre el 11 y este: modelo *Running* y suscripción MaaS del módulo 9.

Este módulo deja *Develop & train → Evaluations* usable desde la web (TrustyAI + MLflow + EvalHub).

== Qué instala

[cols="2,3"]
|===
| Pieza | Para qué

| `trustyai` Managed
| Operator TrustyAI (CRD `EvalHub`)

| `mlflowoperator` Managed + CR `mlflow`
| Tracking de experimentos (requerido por la UI Evaluations)

| Postgres efímero en `evalhub`
| Backend del EvalHub Server (lab)

| `EvalHub` CR + `MLFLOW_TRACKING_URI`
| Jobs de eval + log a MLflow

| `disableLMEval: false`
| Menú *Develop & train → Evaluations*
|===

== Script (recomendado)

[source,bash]
----
# Modelo arriba (si lo paraste por CPU):
oc patch llminferenceservice qwenqwen3-06b -n llm --type=merge -p '{"spec":{"replicas":1}}'

bash examples/apply-evalhub.sh
----

Espera TrustyAI/MLflow Ready y pods de EvalHub. Hard refresh del dashboard (`Cmd+Shift+R`).

== Paso a paso

=== 1. Operators en el DSC

[source,bash]
----
oc patch dsc default-dsc --type=merge -p '{
  "spec":{
    "components":{
      "trustyai":{"managementState":"Managed"},
      "mlflowoperator":{"managementState":"Managed"}
    }
  }
}'
----

Espera `TrustyAIReady=True` y `MLflowOperatorReady=True`.

=== 2. Flags del dashboard

[source,bash]
----
oc patch odhdashboardconfig odh-dashboard-config -n redhat-ods-applications --type merge -p '{
  "spec":{"dashboardConfig":{"disableLMEval":false,"genAiStudio":true}}
}'
----

=== 3. MLflow (lab: SQLite + PVC)

[source,bash]
----
oc apply -f examples/evalhub/mlflow.yaml
oc get pods -n redhat-ods-applications | grep -i mlflow
----

=== 4. EvalHub

[source,bash]
----
oc apply -k examples/evalhub
oc get evalhub,pods,route -n evalhub
----

== UI — lanzar la evaluación

. Dashboard → *Develop & train* → *Experiments (MLflow)* → proyecto `llm` (o el tuyo)
. Crea un experimento, p. ej. `qwen-smoke`
. *Develop & train* → *Evaluations* → *Start evaluation run*
. Benchmark: *Helpfulness, honesty & harmlessness (HHH)* (en este build **no** aparece `hellaswag` en la lista UI). En *Benchmark parameters*:

[source,json]
----
{"limit": 5, "num_fewshot": 0}
----

. *MLflow experiment*: el que creaste
. *Source*: modelo desplegado / endpoint MaaS (`publishers/llm/models/...`)
. *Evaluate*

Espera *Completed* (el smoke suele ser *5–15 min* en OpenTLC). Luego *Experiments (MLflow)* para ver métricas del run.

Tras el job, *Observe & monitor → Usage* mostrará el spike de tokens (por eso EvalHub va *después* del módulo 11).

== API (backup)

Si la UI no lista el modelo, usa API/CLI con `benchmark_id` del provider (p. ej. el id interno de HHH / `bigbench_hhh_alignment_multiple_choice`) y `limit: 5`.
