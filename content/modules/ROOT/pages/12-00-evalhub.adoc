= EvalHub (evaluación del modelo)

Prueba de calidad *después* de xref:11-00-observabilidad.adoc[observabilidad MaaS], para no ensuciar los dashboards de Usage con el tráfico del benchmark.

Nada más obligatorio entre el módulo 11 y este: el modelo debe estar *Running* (Start si lo dejaste parado) y la suscripción MaaS del módulo 9 activa.

== Qué instala

[cols="2,3"]
|===
| Pieza | Para qué

| `trustyai` Managed en el DSC
| Operator TrustyAI (EvalHub CRD)

| Postgres efímero en `evalhub`
| Backend del EvalHub Server (lab only)

| `EvalHub` CR
| API de jobs + provider `lm-evaluation-harness`

| `disableEvalHub: false`
| Página *Develop & train → Evaluations* (si usas UI + MLflow)
|===

NOTE: La UI *Evaluations* de RHOAI 3.5 también pide un servidor *MLflow*. En este lab la prueba smoke va por *API/CLI* (sin MLflow) para no sumar otro stack en OpenTLC. MLflow queda como GAP → Prd.

== Paso a paso

=== 1. TrustyAI en el DataScienceCluster

[source,bash]
----
oc patch dsc default-dsc --type=merge -p '{
  "spec":{"components":{"trustyai":{"managementState":"Managed"}}}
}'
oc get dsc default-dsc -o jsonpath='{.status.conditions[?(@.type=="TrustyAIReady")].status}{"\n"}'
----

Espera `TrustyAIReady=True` (unos minutos).

=== 2. Flag del dashboard

[source,bash]
----
oc patch odhdashboardconfig odh-dashboard-config -n redhat-ods-applications --type merge -p '{
  "spec":{"dashboardConfig":{"disableEvalHub":false}}
}'
----

=== 3. Deploy EvalHub

[source,bash]
----
oc apply -k examples/evalhub
oc rollout status deploy/evalhub-postgres -n evalhub --timeout=300s
oc get pods -n evalhub
oc get route -n evalhub
----

== Smoke eval (API)

Eval corta: *hellaswag* con `limit: 5` (minutos, no una suite completa). Endpoint OpenAI-compatible del gateway MaaS (in-cluster) + API key del módulo 10.

[source,bash]
----
EVALHUB_URL="https://$(oc get route -n evalhub -o jsonpath='{.items[0].spec.host}')"
TOKEN="$(oc whoami -t)"
TENANT=llm

CLUSTER_DOMAIN=$(oc get ingresses.config/cluster -o jsonpath='{.spec.domain}')
MAAS_URL="maas.${CLUSTER_DOMAIN}"

# Reutiliza o crea API_KEY (módulo 10)
: "${API_KEY:?export API_KEY from module 10}"

oc -n evalhub create secret generic maas-api-key \
  --from-literal=api-key="${API_KEY}" \
  --dry-run=client -o yaml | oc apply -f -

MODEL_URL="http://maas-default-gateway-openshift-default.openshift-ingress.svc.cluster.local/v1"
MODEL_ID=$(curl -sk "https://${MAAS_URL}/v1/models" \
  -H "Authorization: Bearer ${API_KEY}" | jq -r '.data[0].id')

curl -sk -X POST "${EVALHUB_URL}/api/v1/evaluations/jobs" \
  -H "Authorization: Bearer ${TOKEN}" \
  -H "Content-Type: application/json" \
  -H "X-Tenant: ${TENANT}" \
  -d "{
    \"name\": \"qwen-smoke-hellaswag\",
    \"model\": {
      \"url\": \"${MODEL_URL}\",
      \"name\": \"${MODEL_ID}\",
      \"auth\": { \"type\": \"api_key\", \"secret_ref\": \"maas-api-key\" }
    },
    \"benchmarks\": [{
      \"provider_id\": \"lm_evaluation_harness\",
      \"benchmark_id\": \"hellaswag\",
      \"parameters\": { \"limit\": 5, \"num_fewshot\": 0 }
    }]
  }" | jq .
----

Sigue el job:

[source,bash]
----
JOB_ID=<id del JSON>
curl -sk -H "Authorization: Bearer ${TOKEN}" -H "X-Tenant: ${TENANT}" \
  "${EVALHUB_URL}/api/v1/evaluations/jobs/${JOB_ID}" | jq '{state, results}'
oc get jobs,pods -n llm | head -20
----

Tras `completed`, vuelve a *Observe & monitor → Usage*: verás el spike de tokens del eval (por eso va *después* del módulo 11).

== UI (opcional, con MLflow)

Si más adelante activas `mlflowoperator` + un tracking server:

. Source = modelo / endpoint MaaS; parámetros `limit: 5`
. *Evaluate*
